# Local Solidity reproduction boundary

This leaf accepts self-contained Solidity standard-JSON source input and a
reviewed official compiler build. It compiles through a separately signed
Swift/JavaScriptCore helper and returns an opaque reproduced artifact. It does
not fetch sources, possess wallet handles, simulate transactions or approve a
write. `chain-evm` independently matches the complete reproduced runtime to
MPT-proved code and qualifies execution/effects.

The source provider supplies untrusted source/settings only. Its ABI, compilation
output, storage layout, proxy descriptions and verification status cannot create
`ReproducedArtifact`. The local compiler supplies those values. Compiler
checksums are closed public upstream build pins, not contract/function allowlists.
Source/compiler labels and hashes in a model call grant no trust.

## Execution and trust

The official Solidity compiler, macOS JavaScriptCore and this helper are explicit
trusted compilation components. Compiler correctness is not established by code
signing. The parent pins its helper and compiler-role XPC broker SHA256/CDHash
into its loaded Mach-O image and cross-checks both pin cohorts. The mandatory
`worker-transport` route authenticates the broker before receiving anonymous data
pipes. That fixed broker launches and attests its actual unreaped helper, then
seals itself with a deny-default policy before Ready. Raw helper paths and
alternate compiler URLs are not public constructors. Every compiler byte is
SHA256-checked before execution. There is no direct-launch fallback for qualified
compilation.

The helper gets source and compiler data on stdin. Its mandatory OS sandbox has
no network, profile, vault or workspace access. No import callbacks or filesystem
source resolution exist. Input is limited to 64 source files, 2 MiB aggregate
source contents and 4 MiB standard JSON. The worker has a 45-second CPU limit,
60-second total deadline, 2 GiB resident/physical memory watchdog and bounded
input/output pipes. Cancellation requires an authenticated actual-worker reaping
receipt. Missing cleanup evidence poisons future compilation in that host
process. Source code is data passed to the compiler, never JavaScript evaluated
by the helper. The worker validates its mandatory read-only lifetime pipe before
input and exits on EOF, unexpected data or an error; that guardian supplements
actual reaping evidence rather than replacing it.

`native_identity.rs` owns fixed loaded-host section lookup. Its direct-child
identity functions and `native_memory.rs` resource accounting are diagnostic
test-only code; packaged compilation uses the native broker's mandatory identity
and resource checks. The distinct compiler identity and resource limits do not
share simulator role/state-broker authority. There is no model-visible PID,
descriptor, process or memory API.

## Compiler provenance and licences

`compiler-catalogue.json` retains exact stable upstream build checksums and the
official inventory snapshot SHA256. Compiler code is downloaded from the fixed
Solidity binary origin only when needed, then reverified on every use. The
compiler is an external GPL-3.0 program executed through standard JSON in a
separate process; it is not linked into the Apache-2.0 application. Its licence
and source provenance must accompany the public compiler cache/distribution.
The standalone Swift helper and its self-contained build script are GPL-3.0-only.
The package includes their complete corresponding source, entitlements, build
instructions, official compiler catalogue and full GPL text under
`third-party-notices/solidity-compiler`. The same closed SHA256 resource manifest
checks canonical source files and actual bundle bytes; missing, extra, indirect
or modified resources reject staging/verification. The Rust supervisor remains
an independent Apache-2.0 component and no GPL dependency is linked into it.
The compiler does not impose its licence on independently authored source or
generated bytecode. JavaScriptCore is supplied by macOS.

Ordinary `reproduce` remains strict and rejects nonempty immutable references.
The chain owner's targeted `reproduce_for_runtime` accepts independently proved
runtime bytes and compares them against the official compiler's template. Only
compiler-enumerated, disjoint 32-byte immutable placeholders may differ; every
other byte, including metadata, must match exactly. All occurrences of one
resolved AST declaration must carry the same word. The artifact retains that
actual runtime and canonical typed bindings in its commitment. Primitive values
have exact width/sign/padding checks. Contract-typed declarations resolve to an
actual compiler AST `ContractDefinition` and a canonical 160-bit address; enum,
function and unresolved user-defined value types remain unsupported. Links still
reject. This leaf cannot certify the supplied bytes as onchain: current MPT code
proofs and snapshot/canonical correspondence remain with `chain-evm`.

Observed immutable values establish no constructor execution, original creator,
initial state or deployment invariant. Typed addresses do not independently
qualify external code/calls or mutable proxy dispatch. Unchanged templates keep
their existing commitments. Canonical integer conversion uses the already locked
`ruint` with only `std`; no Alloy/legacy signing-math dependency is added to this
leaf. Arbitrary business semantics are never inferred from source names.

The packaged broker's live-child accounting uses exact kernel rusage, with a
strict read-only SDK task-name fallback where needed. Missing or truncated
accounting rejects; the first successful measurement precedes source input.
Debug-only opt-in stage markers expose fixed host stages, never helper stderr,
arbitrary details or secret input. The independently launched broker avoids the
known nested `sandbox-exec` denial under the main App Sandbox while preserving
both mandatory deny-default profiles. Actual packaged qualification remains a
separate release check; ordinary unit tests do not establish it.
